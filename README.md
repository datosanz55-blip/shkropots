# ShkrobotS — лендинг

Одностраничный сайт для ShkrobotS Loft Studio
(лофт-мебель и мягкая мебель на заказ, Челябинск).

  logo.jpg            — логотип (белая графика на тёмном фоне)

## Перед каждым деплоем

```bash
./preflight.sh
```

Ловит самый частый класс ошибок: файл есть в репозитории, разметка на него
ссылается, а в образ он не попал — забыли дописать в `COPY` в Dockerfile или
отсёк `.dockerignore`. Локально через `file://` всё открывается, на проде —
пустые места и битые картинки. Проверяет 557 ссылок из HTML/CSS/JS, список
`COPY`, `.dockerignore`, целостность каталога и не осталась ли заглушка домена.
Возвращает 1 при проблемах, так что годится в CI или pre-push hook.

## Домен

Домен прописан в 12 местах: canonical и Open Graph на двух страницах,
JSON-LD, `robots.txt`, `sitemap.xml`. Менять руками не нужно:

```bash
./set-domain.sh shkrobots.ru
git diff --stat
```

Скрипт идемпотентный, запускается из корня репозитория.

## Локальный запуск

Просто открой `index.html` в браузере — сборка не нужна.

Проверить именно в контейнере (как на проде):

```bash
docker build -t shkropots-web .
docker run --rm -p 8080:80 shkropots-web
# открыть http://localhost:8080
```

Или через Compose:

```bash
docker compose up --build
# открыть http://localhost:8080
```

## Что было починено в деплое (проверено на живом nginx)

Конфиг прогонялся локально через `nginx -t` и запросами `curl`. Нашлось четыре
вещи, из-за которых сайт вёл себя не так, как выглядел:

1. **`listen [::]:80` роняет контейнер.** В Docker IPv6 по умолчанию выключен,
   nginx падает на старте с `socket() [::]:80 failed (97: Address family not
   supported by protocol)` и уходит в крэш-луп. IPv6-слушатель убран: наружу
   смотрит Traefik, внутрь он ходит по IPv4.

2. **Security-заголовки не доходили ни до одной страницы.** В nginx `add_header`
   в `location` обнуляет все унаследованные от `server`. Заголовки стояли один
   раз в `server{}`, а в каждом `location` был свой `add_header Cache-Control` —
   и затирал их. Проверка показывала их только на `/healthz`. Вынесены в
   `nginx-security.conf` и подключаются в каждый `location`; стало 4 из 4 везде.

3. **Битые адреса отдавали лендинг с кодом 200.** `try_files $uri $uri/
   /index.html` — фолбэк для SPA, которого тут нет. `/abracadabra` и даже
   `/catalog` возвращали главную страницу с её `<title>`, то есть поисковик
   индексировал бесконечные копии главной. Теперь `try_files $uri $uri.html
   $uri/ =404`: `/catalog` открывает каталог, несуществующее — 404.html.

4. **Картинки получали два разных `Cache-Control`** — от `expires` и от
   `add_header` одновременно. Осталась одна директива на location.

Попутно: `gzip_types` дополнен `text/javascript` (nginx менял mime-тип для .js
между версиями, при несовпадении сжатие молча отключается), добавлены
`charset utf-8` (в каталоге русские названия), `server_tokens off`,
`RUN nginx -t` в Dockerfile (кривой конфиг роняет сборку, а не прод),
health-check переведён на `/healthz`. Из `docker-compose.yml` убран
`ports: 8080:80` — он открывал сайт по голому HTTP в обход Traefik и HTTPS.

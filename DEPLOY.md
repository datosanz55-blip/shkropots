# Деплой

## Правило №1: сервер — не исходник

Единственный источник правды — репозиторий. На сервере лежит **копия**, которую
Dokploy перезаписывает при каждом деплое.

Любая правка, сделанная прямо на сервере, живёт до первого `git pull`.
Выглядит это так: поменяли ссылку через `sed -i` в
`/etc/dokploy/applications/<app>/code/src/...`, сайт заработал, через неделю
деплой — и ссылка снова старая. Искать причину будут долго, потому что в
репозитории правки никогда и не было.

**Правильный цикл:**

```
правка локально → ./preflight.sh → git commit → git push → Deploy в Dokploy
```

## Первый деплой

1. Dokploy → **Create Service** → **Application**
2. **Source**: этот репозиторий, ветка `claude/furniture-shop-deploy-build-q0anw5`
   (или `main` после слияния)
3. **Build Type**: `Dockerfile`, путь — `Dockerfile`
4. **Domains**: домен, **Container Port = 80**, включить HTTPS (Let's Encrypt)
5. Перед первым деплоем заменить домен-заглушку:
   `./set-domain.sh <домен>`, закоммитить, запушить
6. **Deploy**

Порт наружу не публикуется: Traefik ходит в контейнер по внутренней сети.
Если в `docker-compose.yml` появится `ports: 8080:80` — сайт станет доступен
по голому HTTP в обход Traefik и сертификата.

## Обновление

```bash
./preflight.sh          # 0 — можно, 1 — деплой остановить
git push
```

Дальше **Deploy** в Dokploy. Всё.

## Чего не делать

**Не поднимать контейнер руками.** Команда вида

```bash
docker run -d --name site --network ... --label "traefik.http.routers..." ...
```

уводит контейнер из-под Dokploy. Он продолжает работать, но Dokploy о нём не
знает: следующий деплой поднимет второй контейнер, и два роутера Traefik начнут
спорить за один домен. Метки, сеть и имя придётся вести руками вечно.

**Не пересоздавать `Dockerfile` и `nginx.conf` на сервере.** Если при сборке
видно

```
ERROR: failed to solve: failed to read dockerfile: open Dockerfile: no such file or directory
```

это значит, что файла нет **в репозитории**, а не на сервере. Написать его
заново через `cat > Dockerfile << EOF` — починить симптом и потерять конфиг:
вместе с ним уедут gzip, кеширование, security-заголовки и маршруты. Чинить
нужно в репозитории. `./preflight.sh` ловит это заранее — пункт «Под контролем git».

**Не собирать проект на хосте.** Здесь сборки нет вообще: в образ копируются
готовые файлы. Сломать нечем — и это осознанный выбор, а не упрощение.

**Не добавлять файлы сборки в `.gitignore`.** Именно так теряли `Dockerfile`:
генератор сайта прописал его в `.gitignore`, при клоне файл не приезжал, сборка
падала, его писали заново на сервере — и так по кругу после каждого деплоя.
`./preflight.sh` предупреждает, если такой шаблон появится.

## Специфика Beget

**Сайт не открывается снаружи, хотя на сервере отвечает.** Известная засада
Beget VPS. Проверять по порядку, каждый шаг отсекает причину:

```bash
nslookup <домен>                     # должен вернуть IP сервера
ufw status                           # inactive либо открыты 80/443
docker ps | grep traefik             # Traefik поднят?
curl -s -o /dev/null -w '%{http_code}\n' http://localhost   # сервер отвечает изнутри?
```

Если все четыре в порядке, а снаружи по-прежнему не открывается — порты 80 и
443 закрыты для входящих на стороне Beget. Чинится только обращением в их
поддержку, со стороны сервера сделать нечего.

Traefik не поднят:

```bash
docker start dokploy-traefik
```

**Traefik и `-p 80:80` несовместимы.** Если контейнер опубликует порт 80,
Traefik не стартует: порт занят. Симптом — Traefik падает сразу после запуска,
а сайт доступен только по `http://<IP>` без сертификата. Поэтому в
`docker-compose.yml` стоит `expose`, а не `ports`, и добавлять туда `ports`
нельзя.

**SSH открывается в `~`.** Команды из таблицы ниже пишите с полным путём,
иначе они выполнятся не там.

## Если сломалось

| Что видно | Где смотреть |
|---|---|
| Контейнер перезапускается | Dokploy → Logs, или `docker logs <контейнер>` по SSH |
| 502 от Traefik | контейнер не поднялся или Container Port не 80 |
| Нет HTTPS | DNS домена не указывает на сервер — Let's Encrypt не выдаст сертификат |
| Белая страница, нет стилей | файл не попал в образ — `./preflight.sh`, пункт 2 |
| Правка не применилась | не закоммичена или деплой шёл со старой ветки |
| Сайт открывается только через VPN | порты 80/443 закрыты у Beget — см. выше |
| Traefik падает после старта | какой-то контейнер занял порт 80 (`ports:` вместо `expose:`) |

Кривой `nginx.conf` до прода не доедет: в `Dockerfile` стоит `RUN nginx -t`,
сборка падает на этом шаге.

## Проверка после деплоя

```bash
curl -I https://<домен>/                 # 200, Cache-Control: no-cache
curl -I https://<домен>/catalog          # 200 — каталог, не лендинг
curl -o /dev/null -w '%{http_code}\n' https://<домен>/abracadabra   # 404
curl -s https://<домен>/healthz          # ok
curl -I -H 'Accept-Encoding: gzip' https://<домен>/styles.css | grep -i encoding
```

Если `/catalog` отдаёт лендинг или битый адрес возвращает 200 — в образе
старый `nginx.conf`.
